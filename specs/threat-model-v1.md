# AgentOps Guard 威胁模型 v1

日期：2026-09-04

## 保护目标

系统首先保护三件事：Agent 不能越权做动作；审批后的内容不能被偷换；密钥只能在受信执行组件
内部解析并注入固定认证字段。扫描检出率重要，但不能代替这三条确定性门禁。

## 信任边界

- 不可信：用户输入、网页/邮件/文档、Agent 生成内容、MCP 工具说明和结果、上游错误正文。
- 经过验证后可信：OIDC 签名中的主体和范围、服务端项目成员关系、服务端保存的原始要求、
  数据库中的工具版本与策略快照。
- 高权限受信组件：API、Gateway、Worker、OpenBao 和隔离运行器。模型服务与 Agent 永远不属于
  密钥信任边界；Gateway 只能向模型服务发送已脱敏且长度受限的文本。

## 主要威胁与处理

| 威胁 | 预防 | 发现 | 故障动作 | 残余风险 |
| --- | --- | --- | --- | --- |
| 伪造项目、Agent 或角色 | 只使用已认证身份；正文身份不能覆盖；人员、Agent、执行者权限分开 | 负向权限测试和审计主体 | 401/403/404，调用不上游 | 身份平台自身被攻破不在本项目内解决 |
| 从新协议入口绕过门禁 | 标准 MCP 服务端直接复用既有工具、固定资源、资源模板、提示与补全处理；不用第二套策略与执行实现 | `1.9.4`、`1.29.1`、`2.1.1` 工具主路径以及当前 SDK 的资源模板与补全均经真实 Gateway 与上游进程测试 | 权限不足或策略不允许时不调用上游；任意未登记资源/提示、未声明补全参数和受限 Agent 读取被拒绝 | 长任务、订阅以及旧 SDK 的资源模板/补全矩阵仍需补齐 |
| 工具说明带隐藏指令 | 来源标为外部；扫描后隔离；只有注册且激活的工具可调用 | 风险事件、隔离状态、回归集 | 不把说明暴露给 Agent，不调用工具 | 未知表达可能漏检，因此高风险动作还需授权门禁 |
| 外部内容伪造可信来源 | 递归删除上游 `io.agentops/*` 元数据；Gateway 重建来源、可信度、变换和不透明引用；未知来源及未知父可信度默认不可信 | 标准 MCP、兼容 API、派生内容和持久化引用合同测试 | 客户端缺少标记时按不可信数据处理，不能升级为指令 | 第三方 Agent 框架可能丢弃 `_meta`，因此动作授权不能依赖标记 |
| 参数或目标被偷换 | 原始要求与动作/目标对齐；审批绑定 RFC 8785 参数摘要 | 版本和摘要漂移测试 | 旧审批失效，重新审批 | 语义等价但写法不同会重新审批，影响便利性 |
| 审批竞争或重复使用 | 执行封套原子领取；身份、运行、工具、策略和到期时间全部绑定 | 10 路真实 PostgreSQL 并发测试 | 仅一个领取者成功，其余不执行 | 外部工具若不支持幂等，超时后仍可能结果未知 |
| 密钥进入消息、参数、URL、日志或模型 | Agent 只持有 `credential_ref`；固定目标注入；输入输出扫描；错误只留固定代码 | 专用假密钥回归和内容引用检查 | 检出即拒绝或脱敏；凭据服务失败时不调用 | 受信进程或宿主机被攻破仍可能泄漏 |
| PostgreSQL 已提交而 Redis 未收到 | Job 与发件箱同事务；固定消息号投递 | 待投递数量和最老等待时间 | Redis 恢复后继续投递 | 长期故障会积压，需要告警和容量预留 |
| Worker 宕机或重复消费 | 原子领取、每分钟续租、固定发件箱编号投递前先查现有 RQ Job、最多三次恢复 | 租约过期、尝试次数、`dead` 状态和失败任务页面 | 安全内部任务重试；超过次数停止 | 真实 Worker 终止、重复投递和 Redis 停止恢复已演练；数据库切换和长时间积压仍未演练 |
| 上游超时或连接断开 | 硬调用时限、并发上限；错误正文不回传 | `outcome_unknown`、固定错误码 | 高风险动作不自动重试，需查询上游或人工核对 | 本地真实进程已证明不会重复执行；上游没有查询或幂等能力时仍无法证明是否执行 |
| 多个网关副本同时压垮上游 | Redis 原子容量租约按上游共享；部署模板禁止多副本使用本地锁 | 429/503 指标、跨进程测试和真实双 Gateway HTTP 演练 | 满额拒绝；Redis 不可用时不调用上游，审批领取退回 | 尚未在目标峰值下持续 30 分钟压测 |
| 审计历史被删除或改写 | 项目内前向哈希链；OpenBao 不可导出 Ed25519 密钥签署链头 | 链检查和签名封条验签 | 报告断链或封条失配并停止把该链当作可信证据 | 必须把公开封条复制到独立只追加存储；只留在同一数据库仍可被整体回滚 |
| 监控链路泄露请求数据 | Span 只保存请求方法、路由模板、状态和固定组件名，不保存动态路径、查询、头或正文；不启用通用 OTel 环境资源自动探测 | 动态路径、未命中路径和环境资源假数据回归；真实 Collector 验收入口检查导出文件 | 发现私密标记即验收失败，不接生产后端 | 仍需在企业 Collector 和后端验证处理器、权限和保留期 |
| 远程镜像构建收到私密仓库文件 | Python 与 Dashboard 分别使用默认拒绝的 `.dockerignore` 白名单，只发送 Dockerfile 实际复制的源码和锁文件 | 合同测试固定允许列表；构建日志核对上下文体积 | 白名单缺失或放入 `.env`、模型、数据集、报告、数据库和缓存时发布失败 | 构建平台本身仍需最小权限、隔离和审计 |
| Dashboard 运行时读取仓库秘密 | Compose 只读挂载构建所需目录和配置文件，依赖与构建输出使用两个独立卷，不挂载整个 Dashboard 或仓库根目录 | 配置合同测试精确枚举全部 Dashboard 卷，并禁止任何服务使用 `.:/app` | 允许列表变化即发布失败 | Compose 仍只限开发，不允许放入生产凭据 |
| 开发服务暴露到局域网 | Compose 的所有宿主机端口只绑定 `127.0.0.1`，跨机器访问必须经过明确入口 | 配置合同测试枚举全部发布端口 | 任一端口缺少回环绑定即发布失败 | 宿主机本身被攻破不在 Compose 边界内解决 |
| 模型误判或不可用 | 模型只旁路；硬规则与授权独立 | 分开统计规则、模型和并集 | 模型失败不改变放行结果 | 未知攻击主要依赖规则和确定性动作门禁 |

## 数据流

1. 标准 MCP 入口或兼容入口把经过验证的身份交给同一组 Gateway 处理函数，查询参数、正文和
   MCP 元数据不能改写身份。
2. Gateway 从数据库取得工具版本、原始用户要求和策略版本，扫描参数并作动作/目标对齐。
3. 低风险且已授权的调用进入上游；高风险调用只生成不含原始参数的执行封套和审批。
4. 审批后 Agent 必须精确重提；Gateway 核对所有摘要并原子领取，随后只执行一次。
5. Gateway 删除上游伪造的 AgentOps 元数据，为外部结果生成不可信来源标记，并把它与脱敏内容
   引用一起保存；摘要、拼接等派生内容使用最严格的父可信度。
6. `credential_ref` 只在受信组件内解析，认证字段只注入固定目标；错误正文不返回 Agent。
7. 决策、审批、执行状态和脱敏审计写入 PostgreSQL；后台任务通过事务发件箱投递。
8. 管理员按周期请求 OpenBao 为链头签名，并把只含公钥和签名的封条保存到独立只追加位置。

## 变更要求

新增外部输入、身份类型、工具传输、凭据提供方或可产生副作用的动作时，必须先在本文件增加
威胁、故障动作和残余风险，再实现代码和负向测试。
