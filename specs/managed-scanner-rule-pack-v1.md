# 受管扫描规则包 v1

## 结论

项目已把真实 Agent 动态测试暴露出的 AgentDojo `important_instructions` 规则盲区做成受管规则包，
并接入 Compose 与 Helm 的数据库迁移任务。修复后回归命中 7/7 条已知攻击，在 302 条公开正常
样本上误报 0 条。

这是一项针对已发现问题的回归结果，不是未知攻击泛化率。旁路小模型仍不参与放行、审批或拦截。

## 规则包怎样工作

规则包位于 `policies/scanner/agentdojo-important-instructions-v1.json`，固定记录：

- 包编号和语义版本；
- AgentDojo 包版本、基准版本、许可证和公开来源；
- 规则编号、标签、模式、风险级别、固定风险分和用途说明。

迁移入口 `agentops-guard-migrate` 先执行 Alembic，再把规则包安装到默认项目。安装编号由“项目、
规则包、版本、规则编号”共同计算，同一版本重复部署只会核对现有内容，不会重复创建。数据库中的
已安装内容只要与审阅包不同，部署立即失败；普通管理员更新或删除受管规则会返回冲突，避免线上
静默改写已评测规则。安装动作进入审计链，审计只保存包摘要、版本、标签和状态。

规则没有简单匹配“important”或工具名，而是同时要求外部内容具有信息块、冒充用户给模型留言、
要求先执行另一项动作、随后继续原任务等完整结构。这样可以避免把正常业务中的“重要”或历史工具
记录直接当成攻击。

管理员可配置规则不再交给会回溯的 Python 正则执行；当前固定使用官方
`google-re2 1.1.20251105`。表达式最长 4,096 个字符，编译内存上限为 8 MiB；后视、反向引用、前瞻等
RE2 不支持的写法会在创建、更新或规则包安装时拒绝。即使配置 `(a+)+$` 这类常见回溯攻击模式，
扫描 10 万字符的对抗输入也不会进入指数级回溯。内置规则仍是随代码审阅发布的固定规则。

## 证据边界

- 规则就是根据这 7 条攻击结构编写的，所以 7/7 只能证明修复没有回退。
- 302 条正常样本扩大了误报检查，但不是线上所有语言、行业和内容形态。
- 规则只补一个高精度攻击结构，不替代旁路语义模型和确定性工具授权。
- RE2 防止规则表达式导致指数级回溯，不提高未知攻击的语义泛化能力。
- 真正未知的新写法即使绕过内容扫描，写入、发送、删除、付款和权限变更仍必须与服务端保存的
  原始用户要求一致，否则进入逐事件审批。
