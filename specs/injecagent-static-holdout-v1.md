# InjecAgent 外部工具内容首次静态保留集 v1

## 一句话结论

项目直接复用 UIUC InjecAgent 固定提交中的 `base` 工具响应，在不使用这些案例写规则、选阈值或
调整模型的前提下完成一次不可覆盖的静态扫描。当时冻结的规则与旁路模型联合检出 `577/1054`
（54.74%）；17 个按用户工具配对的正常响应模板中误报 `1`（5.88%）。结果证明小模型已经启用并
承担主要检出，但距离强制拦截标准仍很远。

当前语义输入边界已经从 512 扩大到 1,024 字符，本报告没有在修改后重跑，因此它是首次运行的
历史盲测证据，不代表当前扫描器数值；同一数据已经失去盲测身份，不能用重跑结果替换首次结果。

- 官方仓库：<https://github.com/uiuc-kang-lab/InjecAgent>

- 官方运行器面向旧云模型接口并保存逐条模型输出，因此没有直接放入生产路径。本项目只实现
  内容寻址加载、当前扫描器适配、汇总报告和保留集生命周期。

来源锁位于 `evals/injecagent-source.json`。评测数据只保存在仓库外的裸 Git 缓存中；加载时核对
提交、许可证、官方运行器和两份数据文件的 Git 对象 SHA-256。

## 结果

| 范围 | 规则 | 旁路模型 | 联合 |
| --- | ---: | ---: | ---: |
| 全部攻击 1,054 条 | 20（1.90%） | 571（54.17%） | 577（54.74%） |
| 数据窃取 544 条 | 19（3.49%） | 438（80.51%） | 444（81.62%） |
| 直接伤害 510 条 | 1（0.20%） | 133（26.08%） | 133（26.08%） |
| 匹配正常模板 17 条 | 0 | 1（5.88%） | 1（5.88%） |

4 个 CPU Worker 下，全部攻击的顺序扫描 p50 为 `110.332ms`、p95 为 `167.557ms`；其中规则
p95 为 `0.262ms`，模型 p95 为 `167.299ms`。这些数值只用于当前机器的扫描回归，不代表网关生产
端到端延迟。

### 解释

- 小模型比规则多发现了大量陌生表达，说明它不是“未启用”。
- 数据窃取通常包含读取、收集或发送信息的语义，小模型识别相对较好。
- 直接伤害中的财务和现实动作可以写得像普通业务要求，缺少传统的“忽略指令”措辞，因此输入
  扫描器难以仅凭一段文本判断它是否获得用户授权。
- 这进一步支持当前架构：扫描负责预警，动作与原始用户要求的确定性对齐负责阻止真实副作用。

## 正常对照的限制

InjecAgent 官方发布物没有与每个攻击案例一一对应的独立正常集合。本项目从每个官方用户工具的
响应模板中删除攻击占位符并填入固定中性句子，得到 17 个唯一匹配对照。它们适合发现明显模板
误报，但样本太少，不能据此宣称真实业务误报率为 5.88%，也不能替代中文正常难例。

## 不能据此声称什么

- 不是 InjecAgent 官方 Prompted Agent 的攻击成功率；本轮没有让 Agent 执行官方攻击工具。
- 不是 AgentOps Guard 端到端阻断率；本轮只扫描工具返回正文。
- 不是小模型可以强制拦截的依据；54.74% 检出和 1/17 匹配模板误报均未达晋级门槛。
- 不是中文或多语言泛化结果。
- 同一集合从首次运行结束起只能用于回归，不能重新称为盲测。
