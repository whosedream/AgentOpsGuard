## 范围与不可混淆的边界

- 保留标准同步网关、真实项目身份、内置规则/策略包、签名 OPA 策略、原旁路小模型、审批与审计。
- 10 个 kind 节点：1 个控制节点、3 个应用节点、3 个业务 PostgreSQL 节点、3 个接单 PostgreSQL 节点。
- 两组独立 Patroni + PostgreSQL 16；各 3 副本，严格同步复制。接单服务 2 副本、导入器 2 副本，实际走 Outbox → Redis → 常驻 RQ worker，不在控制器内直接执行任务。
- 两个数据库故障节点组分开，但仍共用同一 WSL 主机、物理磁盘和 Kubernetes 控制面，数据库节点组也共享逻辑 CPU 资源。不是物理多机，不认证月度 SLA。
- 接单库切主仍可能短暂拒绝接单。须分别记录未受理、受理后丢失、重复执行、状态查询中断和最终完成，不拿“已接单任务恢复”替换入口可用性指标。
- v2 回执测试只用合成 MCP 工具；业务效果和原结果可靠保存后故意退出进程，由常驻回执进程取回、重新评分及检查权限，不重新执行原动作。

## 本次故障后的开跑保护

1. 在创建产物目录、改宿主额度、建集群之前，读取 Windows 注册表定位该发行版实际所在卷，同时检查宿主系统卷。此十节点实验暂定保守余量：WSL 所在卷至少 50 GiB、系统卷至少 10 GiB；这是实验保护线，不是行业标准或已证明足够的生产容量。
2. 不将 Windows 命令错误输出当 UTF-8 文本解码；仍检查真实退出状态，不把失败伪装成成功。
3. 精确集群编号由外层控制器预先生成并保存在内存中。收尾不再依赖可能读不出的 `state.json`；集群清理、额度恢复分别尝试，二次错误显式报告。即使报告文件写不出，也先向控制器输出脱敏的恢复状态。整个宿主/控制器退出时，仍不能保证程序的 `finally` 能执行。
4. 真实运行新的只读空间预检：正确拒绝继续建集群；监听额度仍为 128。针对保护逻辑及部署脚本的单元测试 **42 passed**，Ruff 与 `git diff --check` 通过。
