# AgentOps Guard MCP 兼容矩阵 v1

日期：2026-09-04

## 支持结论

下游标准入口为 Streamable HTTP `/mcp`。当前发布门槛固定以下客户端锚点；“通过”表示真实客户端
包经 Bearer 鉴权连接真实 Gateway，再调用真实 MCP 上游，不只是构造协议报文：

| 客户端包 | 协商协议 | 初始化 | 工具列表 | 工具调用 | 结论 |
| --- | --- | --- | --- | --- | --- |
| MCP Python SDK `1.9.4` | `2025-03-26` | 通过 | 通过 | 通过 | 最低已测 1.x 锚点 |
| MCP Python SDK `1.29.1` | `2025-11-25` | 通过 | 通过 | 通过 | 最新已测 1.x 锚点 |
| MCP Python SDK `2.1.1` 传统模式 | `2025-11-25` | 通过 | 通过 | 通过 | v2 传统握手分支 |
| MCP Python SDK `2.1.1` 现代模式 | `2026-07-28` | 通过 | 通过 | 通过 | 当前主路径 |

服务端实现直接使用官方 MCP Python SDK `2.1.1`，旧 `/mcp/tools/*` 等 AgentOps HTTP 路由只是
迁移兼容层。标准入口与兼容层调用同一组扫描、策略、审批和审计处理函数。当前 SDK 另以每页一项
跑通工具、固定资源、资源模板和提示各两页；资源模板由官方 RFC 6570 实现解析、展开和匹配，
上游模板地址经项目绑定的不透明引用保护；畸形、跨列表、跨身份和列表变化后的游标统一返回 `-32602`。
当前 SDK 的提示与资源模板补全也走相同保护引用和已公开对象复核；未声明参数、凭据和危险返回值
不会传给上游或客户端。

## 复现入口

- `tests/test_gateway_standard_mcp_server.py`：当前 SDK 的传统与现代协商、权限和审批前不执行。
- `scripts/verify_mcp_v1_client.py`：必须在指定的 MCP 1.x 隔离环境中运行，版本不为 1.x 时失败。
- `scripts/verify_gateway_multi_replica_capacity.py`：启动两个真实 Gateway 和真实上游；设置
  `AGENTOPS_MCP_V1_PYTHON` 后，把旧客户端加入同一主链验证。

旧客户端环境必须由 `uv` 按精确版本单独创建，不能把 1.x 安装进项目的 2.x 运行环境。测试凭据
只通过子进程环境交给本地验证器，不写入命令、URL、报告或日志。

## 边界

- `1.9.4` 是当前最低已测版本，不表示更早版本一定失败，也不承诺支持。
- 当前 SDK 的资源模板与补全主路径已验证；尚未验证旧 SDK 包上的资源模板/补全、客户端任务、订阅和
  恢复令牌等可选能力，服务端只声明实际注册的能力。
- 分页已支持标准 `cursor` / `nextCursor` 字段；游标是不透明、带完整性保护并绑定已认证身份和
  当前可见列表快照的，不能跨列表或跨身份复用。
- 本矩阵是协议与安全主链合同，不代表生产吞吐、长连接稳定性或 30 分钟峰值容量。
