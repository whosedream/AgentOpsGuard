## 结论

本轮已经补上最容易导致越权、偷换审批内容、重复执行和任务丢失的主干控制。当前可以称为
“有真实数据库和进程故障证据的受控生产候选基础”，还不能称为“已经企业级投产”。真实企业
身份平台、真实业务上游的幂等与结果查询、审计封条的外部只追加保存、完整 Agent 攻防和目标环境

## 直接复用的开源实现

- 参数和快照摘要使用 Trail of Bits 的 `rfc8785`，不再自写跨语言数字序列化规则；业务层继续做 NFC 字符归一化。
- OIDC 验签复用 PyJWT 的 JWK 客户端，只接受明确列出的 `RS256` 和 `ES256`。
- 数据库迁移、事务和并发更新继续使用 Alembic 与 SQLAlchemy；异步投递继续使用 Redis/RQ。
- OPA、OpenBao、ToolHive 和官方 MCP SDK 保持为外部能力边界，不复制其内部实现。ToolHive 的
  Sigstore 来源校验和权限配置直接通过 CLI 调用，本项目只固化允许的启动参数和验收条件。
- Kubernetes 镜像准入直接使用 Sigstore policy-controller 的 `v1beta1` CRD 和官方 Helm chart；
  本项目只生成批准的仓库与签名身份策略，不复制 admission webhook。

这里的“复用”是固定依赖和适配边界，不是把陌生仓库整份复制进来。这样更新和漏洞修复仍能
跟随上游，也更容易审计本项目自己承担的安全逻辑。
