# 2026-09-05 高可用演练与中英文识别质量验收

## 结论和范围

本轮验证两个问题：网关进程故障时是否继续服务，以及新攻击与正常难例能否被正确区分。
测试完成不等于所有门槛通过，尤其不能把静态报警率写成真实攻击阻断率。

识别质量未达到既定门槛。英文外部成对测试联合检出率 87.50%、正常难例报警误报率
56.67%；中文自建诊断集分别为 55.00% 和 30.00%。两组不能混为一个总分。

高可用长测也未通过：18,000 次请求有 20 次失败，错误率 0.1111%，超过低于 0.1% 的门槛；
此外有 292 次旁路模型扫描错误。没有发现越权写入、重复读取或已返回策略决策落库缺口。
该演练在单台 WSL 主机上执行，不是独立故障域的生产集群验收；业务峰值尚未提供。

## 1. 真实网关故障演练

`scripts/verify_gateway_ha_soak.py` 使用现成 HAProxy，不自制负载均衡器：

- 固定 HTTP 入口后部署两个真实网关进程，共享 PostgreSQL 16 和 Redis 7。
- 工具由真实 MCP 上游提供；通过已有 `/mcp/tools/call` 入口进入同一策略处理链。
  这不是 MCP 协议全套兼容性评测。
- 安装当前受管扫描规则包，启用固定 Wolf Defender 小模型旁路扫描，以及真实 OPA 1.8.0
  签名规则包校验。模型判断阈值仍为 0.90，没有为演练放宽。
- 本次每个网关本地加载一份小模型，尚未覆盖独立语义服务的副本故障。“旁路”表示模型不直接
  决定放行或拦截，不表示评分没有耗时；这里的往返延迟包含同步模型评分、OPA 和上游通信，不能
  直接当成“不含模型及上游的网关自增耗时”。同机还运行了限定 CPU 范围的回归任务，报告不是
  独占机器的极限性能测试。
- 按固定时钟每秒发起 10 次请求，持续 30 分钟；这只是明确的测试负载，不能称为业务峰值两倍。
- 在第 10、20 分钟分别强制终止一个网关，10 秒后启动替代进程。
- 每 100 次请求中包含一次未授权写入探针，其上游只有受控执行收据，不写用户文件。
- 客户端和负载均衡器均不自动重试。工具执行了但没有成功响应的请求单独计数，不能隐藏在重试里。
- 记录 HTTP 错误、排队延迟、完整往返耗时、重复上游执行、未授权写入、返回决策与落库决策差额，
  并检查旁路模型错误事件。模型失败但 HTTP 成功不能被算成完整安全链路健康。
- 审计哈希链检查覆盖规则包安装记录；每次读取的持久化证据是策略决策，不冒称每次读取都有完整
  Run/Trace/Event 审计链。报告明确区分这两个范围。
- 测试临时服务在退出后清理，输出只保留汇总、版本和摘要，不保存认证信息或工具原文。

短时预检不能替代长测：15 秒基础链路试验共 150 次请求，其中 3 次失败，重复执行和越权写入为 0。

拒绝就绪；这是演练配置错误，已更正，未绕过版本校验。约 4 分钟的准备轮在补齐模型错误计数、
受管规则和代码冻结校验后主动终止，不计入 30 分钟正式验收。

### 本轮修复

Python 3.12 下 `cached_property` 不保证并发首次访问只初始化一次。回归测试用 8 个并发访问者
稳定复现了 8 次模型构造。现在分别串行化扫描器创建和首次模型加载；评分算法、文本窗口、权重、
阈值不变。修复后同一测试只构造 1 次，仍保留推理繁忙时的明确失败，不吞错误或伪造正常评分。

### 仍不能证明的项目

- 整台机器、可用区、负载均衡入口或 Redis 本身故障后的整体服务连续性；
- 实际业务峰值两倍负载、生产数据规模、长文档与攻击密集流量的容量；
- 月度 99.9% 可用性、生产磁盘丢失恢复、跨故障域备份恢复；
- 执行结果未知的外部写入可以自动重试或恰好执行一次。

已有独立的 Patroni 三节点切主演练仍可作为数据库子系统证据，不能据此声称本次网关负载下同步
验证了数据库切主。参见 `specs/patroni-kubernetes-failover-v1.md`。

## 2. 新中英文成对难例

### 数据选择

英文使用 Enes Deniz 发布的
[Agentic Prompt-Injection Boundary Pairs](https://huggingface.co/datasets/3nesdeniz/agentic-prompt-injection-boundary-pairs)
官方 test 划分：120 条攻击、120 条同工作流程正常难例，12 个攻击类别。发布者说明它是人工设计、
人工抽查的合成数据，不是真实入侵记录；按照工作场景隔离训练、验证和测试划分，许可证 CC BY 4.0。
固定版本 `a5682e7573e1c7bc4b12e64d49c0dcd90ca776cf`，源文件 SHA-256：
`034523eefaec18c291f9daa7699037acb0e7a91b1aeb1b205878b124f6e18f10`。

中文使用本轮单独编写的 40 对、80 条诊断样本，覆盖冒充授权、外发数据、滥用工具、污染记忆、
提取隐藏指令、文字混淆、绕过流程及污染外部资料。每对使用相近业务词汇，正常样本要求停在授权
边界前或只分析风险。它不是独立公开中文盲测集，不用于宣称中文真实流量准确率。

选择时排除了以下来源：

- ChangeMore：包含有害内容与越狱标签，不能把所有阳性标签直接当成提示注入标签。
- Rikka 多语言集、Chinese Prompt Injections Benchmark：已列在当前固定小模型的训练来源中，
  其中 Rikka 连 test 文件都在列表里，不能拿来证明模型未知泛化。
- A3S-Bench：适合完整多轮 Agent 评估，但下载的公开会话主要是英文，且攻击标记需要按轮次和
  渠道解释，不应把整个会话粗暴标成单条中文注入文本。

上述模型来源核对采用
[固定版本模型卡](https://huggingface.co/patronus-studio/wolf-defender-prompt-injection-small/blob/eff31df5c97ca127b7b55da255a160f88a625c97/README.md)，
没有换成后来发布的新权重。

### 原因判断和处理决定

英文“混淆编码”类别攻击 10/10 报警，但对应正常难例也 10/10 报警；中文“工具滥用”和
“流程绕过”类别各只命中 1/5 攻击。结果支持以下判断，但不是对模型内部机制的直接证明：

- 小模型能识别不少攻击语气，却难以区分“讨论危险操作”和“要求真正执行危险操作”。
- 同一业务词汇可以出现在攻击和正常任务中，仅增加关键词会同时增加误报。
- 授权是否合法取决于可信用户要求、身份、目标、动作和审批记录，不能由一段文本自行证明。

因此不把小模型升级成自动批准或直接拒绝的最终裁判；保留确定性动作授权兜底。
下一步若改模型或训练分类器，应使用另一批训练/调参数据，并另封一批独立中文与英文难例验收，
不能修改这 320 条后继续称为盲测。现有 92.80% LLMail 成绩仍仅属于固定旧数据分布，不能用来
覆盖这里暴露出的短板。
