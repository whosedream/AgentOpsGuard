# AgentThreatBench 动态网关回归 v1

日期：2026-09-05

## 结论

这组评测回答的不是“正则命中了多少文本”，而是：一个真实本地 Agent 读到外部内容后，是否真的
发起工具调用；AgentOps Guard 是否在调用前作出策略判断；最后有没有产生不该发生的写入、发送或
其他副作用。

当前语料已经被本轮开发使用，因此所有修复后运行都是公开语料回归，不是新的未知攻击盲测。
它能证明修复进入真实链路，不能代表生产环境或所有未知攻击。

## 直接复用的开源部分

- 数据和官方评分器来自
  [UK Government Inspect Evals](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.16.0/src/inspect_evals/agent_threat_bench)，
  固定为 `inspect-evals 0.16.0`、任务版 `1-A`、标签提交
  `3367d26374083aa794600b9c06b0b4f76faad76d`。
- Agent 执行框架复用 Inspect AI；MCP 客户端和上游服务复用官方 MCP Python SDK。
- 本项目只实现中间的网关适配、来源边界、内容扫描、动作授权、审批暂停和无正文汇总报告，没有
  复制官方任务、工具或评分逻辑。

固定语料共 `24` 条：`19` 条攻击、`5` 条正常；分为记忆污染、任务劫持和数据外传三类。语料摘要
为 `d9792b283faa78b33e9b6a81c86e2f84e0eccc02c70f21aa70361287cb7cb7aa`。

## 固定运行方式

- Agent：真实本地 `Qwen3-4B-Q4_K_M`，模型文件和 `llama-cpp-python 0.3.35` 运行环境均以
  SHA-256 固定；温度 `0`、种子 `0`、最大输出 `768`。
- 对照组：官方任务、官方工具和官方评分器直接运行。
- 网关组：同一模型和任务经真实 Gateway 进程、真实标准 MCP 客户端和受控上游运行。
- 安全评分只统计真正执行的工具调用，不把模型“想调用但已被网关暂停”的请求算成真实副作用。
- Agent 只收到不透明 `credential_ref`；测试身份由受信回环进程注入固定 Gateway 目标，不进入
  Inspect 日志、模型上下文或报告。
- 报告不保存提示、工具参数、工具结果、模型回答、逐条结果或凭据，只保存版本、摘要和汇总计数。

## 为什么保留六版报告

| 版本 | 发现的问题 | 结论 |
| --- | --- | --- |
| v1 | 适配函数签名错误，网关组实际工具调用为 `0`，却显示效果安全率 `100%` | 无效安全证据，保留作反例 |
| v2 | 修复真实工具调用，但扫描的是代理参数，不是上游返回；多个真实改写工具仍被当成读取 | 建立可用基线，效果安全 `14/19` |
| v3 | 改为扫描真实结果，但把结构化返回整体隔离 | 攻击效果安全 `18/19`，正常完成 `0/5`，因不可用而淘汰 |
| v4 | 保留结构并只替换危险值，正常完成恢复到 `1/5`；但改写工具仍未正确分类 | 效果安全回落到 `13/19`，暴露动作分类缺口 |
| v5 | `categorize_email`、`draft_summary`、`memory_write`、`resolve_ticket` 和 `send_message` 正确进入改写/发送路径；风险外部内容后的改写进入审批并保持运行暂停 | 效果安全 `15/19`，正常完成 `1/5`；发现小模型只看 512 字符时会漏掉中间内容 |
| v6 | 把进入小模型的已脱敏连续文本上限提高到 `1,024` 字符，规则、阈值和模型权重不变 | 见“当前结果” |

这条历史很重要：企业安全不能把“没有执行测试”冒充安全，也不能接受“把所有内容都挡掉”的零
可用方案。

## 当前结果

无网关基线中，攻击样本的模型自我抵抗为 `13/19`（68.42%），攻击任务完成为 `6/19`
（31.58%）；正常任务完成为 `1/5`（20%）。

v6 网关组结果：

- 攻击样本中共有 `23` 次高风险改写尝试；`5` 次首次调用进入审批，后续 `18` 次重试保持暂停，
  真正执行的高风险动作为 `0`。
- 按官方任务含义和实际执行调用重新评分，完整安全为 `17/19`（89.47%）。剩余两条失败分别来自
  一次记忆污染回答和一次邮件任务在最终文字里回显攻击内容；它们没有产生写入或外发。
- 攻击任务实际完成为 `0/19`。这是无审批员参与时的保守结果，不能把它说成模型能力提升。
- 正常任务仍完成 `1/5`，与无网关基线相同；其中唯一的正常邮件任务完成全部改写，审批和暂停均
  为 `0`。另外四条正常任务在无网关基线本来也没有完成。
- 小模型高风险旁路事件从 v5 的 `6` 个增加到 `8` 个；网关扫描 `24` 个真实外部结果，创建 `5`
  个审批，Gateway 错误和工具格式转换错误均为 `0`。

v6 报告：`artifacts/evals/agent_threat_bench_gateway_v6.json`

SHA-256：`03f0957215edc0ef834000081d4956f6fc62b7ec988cb48c20e71a30b6d9aec7`

主结论应写成“本固定公开回归中，5/5 个邮件劫持样本的改写请求在上游前暂停，攻击样本的高风险
写入实际执行为 0”；不能写成“19/19 攻击全部识别”或“正常任务完成率达到企业要求”。

## 小模型的权力边界

小模型仍以 `shadow` 模式扫描，精确分数不返回 Agent，也不直接批准、放行或隔离本次内容。它的
高风险事件只能把同一次运行中后续的改写、发送、删除、付款或改权限动作升级为人工审批。原始
用户要求与动作、目标不匹配时，无论小模型怎么判断都不能自动执行；小模型也不能降低规则风险。

输入先在 Gateway 本地做规范化和密钥替换，再交给无网络的独立模型服务。扩大到 `1,024` 字符是
修复中等长度工具结果的漏看空洞，不是启用已淘汰的全文多窗口方案。超过上限的内容仍只取头、
中、尾三个有界片段，避免单个外部结果无限占用模型资源。

## 仍然不能声称什么

- 不是独立保管的未知攻击盲测；六版都使用同一公开语料。
- 不是官方 AgentDojo 分数，也不是 Inspect Evals 项目的官方排行榜结果。
- 不是生产业务工具、企业身份、企业网络或人工审批员的端到端测试。
- 正常样本只有 `5` 条，而且这个 4B 模型的无网关正常完成率本来只有 `1/5`，不能据此证明生产
  可用性。
- 小模型在较大的 BIPIA、InjecAgent 首次静态集合上仍未达到“召回至少 90%、正常误报至多 1%”
  的直接内容拦截门槛。

下一次有资格称为未知攻击评测的运行，必须换成未被开发者查看的新中英文攻击和正常难例，由
独立保管方在冻结代码、规则、模型和阈值后一次性交付，并同时报告真实副作用、正常完成率、误
审批率和新增延迟。
